>
> **Проверено на проде (11.10.2026):** тенант `OnixVPN` (`onixvpn`, id 3), бот `@TestChatmodel1BOT`, вебхук `https://sct.chat/api/tg/3`, `pending = 0`, ошибок нет; входящие чаты доходят до панели end-to-end (подтверждено владельцем). `localhost.run` не используется — вебхук смотрит прямо на `sct.chat`.

### 9.1 Схема БД

### Фикс: вход и привязка Telegram молча не работали (18.10.2026)

- [x] **Причина оказалась нашей, а не в Telegram.** helmet по умолчанию ставит
  `Cross-Origin-Opener-Policy: same-origin`. Окно авторизации виджета открывается
  из кросс-доменного фрейма `oauth.telegram.org`; при несовпадении COOP браузер
  изолирует новое окно — `window.open` возвращает `null`, а в самом окне
  `window.opener` = `null`. Дальше срабатывает проверка виджета
  `if (event.source !== TWidgetLogin.activePopup) return;` — подписанные данные
  не доходят до страницы. Снаружи это выглядит так: человек входит в Telegram,
  окно закрывается, и **ничего не происходит, без единой ошибки в интерфейсе**.
- [x] **Как проверялось**: локальный эксперимент с двумя кросс-доменными
  страницами — при `same-origin` `window.open` возвращает `null`, без COOP /
  `unsafe-none` / `same-origin-allow-popups` окно отдаётся. На проде после фикса:
  `window.open` → window, `activePopup` установлен, сообщение
  `{"event":"auth_user",…}` дошло со фрейма, страница отправила
  `POST /auth/telegram/login` и получила 400 на заведомо фальшивую подпись —
  то есть вся цепочка жива, а серверная проверка подписи работает.
- [x] **Фикс** (`backend/src/server.ts`):
  `crossOriginOpenerPolicy: { policy: 'same-origin-allow-popups' }` — защита от
  чужого opener сохраняется, окно виджета работает.
- [x] **Обратная связь при отмене**: `TelegramLoginButton` получил `onUnauthorized`
  (виджет присылает `unauthorized`, если окно закрыли без входа) — страницы
  входа/регистрации/восстановления показывают сообщение, диалог привязки — тост;
  под кнопкой появилась подсказка «Откроется окно Telegram — подтвердите вход».
- **Что помнить**: при первом входе Telegram просит номер телефона и код (в
  браузере ещё нет сессии Telegram Web) — последующие входы в одно нажатие.
  На странице входа незнакомый Telegram создаёт **новый аккаунт с отдельным
  тенантом**, поэтому привязывать Telegram нужно из панели (сайдбар → «Привязать
  Telegram»), а не попыткой входа.

  данных своих клиентов (определяет цели, состав, сроки и получает согласия), сервис
  обрабатывает эти данные исключительно по его поручению и оператором не является.
  Всё, что из этого следует (согласия, состав данных, уведомление РКН, локализация),
  лежит на заказчике; сервис фиксирует это гарантиями и регрессом.

  - квалификация по **цели** использования, а не по наличию ИП: обслуживание своих

## 18. Шаблоны тикетов: файлы, плейсхолдеры, предпросмотр — реализовано 19.10.2026

Приведены в соответствие «заявленные возможности = поведение»: что конструктор
обещает, то форма и делает.

- [x] **Поле «Файл» — настоящая загрузка, а не строка для ссылки.** Новый эндпоинт
  `POST /tickets/upload` (в роутере тикетов — значит, с теми же проверками оплаты
  и тарифа): файл кладётся в хранилище тенанта (`uploads/tenant-<id>/`), в форме
  оператор выбирает файл кнопкой «Загрузить файл», видит имя и может заменить или
  убрать. Значение поля хранится как `{ url, name }`; карточка тикета показывает
  файл кликабельной ссылкой с исходным именем.
- [x] **Имя файла при скачивании.** Раздача `/uploads/*` учитывает `?name=` (панель
  передаёт исходное имя) — браузер сохраняет «чек.pdf», а не «<uuid>.pdf»;
  имя проходит sanitize (`safeDownloadName`), кириллица — через `filename*=UTF-8`.
- [x] **Очистка «осиротевших» файлов учитывает тикеты.** Раньше сборщик мусора
  смотрел только на сообщения чата и удалил бы вложение тикета через 24 часа —
  теперь проверяет и `tickets.data`.
- [x] **Валидация `validateTicketData`** принимает `{ url, name }` и (для старых
  тикетов/интеграций) строку-ссылку; ссылки проверяются (только `/uploads/` или
  http(s), без `..`), так что `javascript:` в поле не сохранится.
- [x] **Общий конфиг загрузки.** `utils/attachmentUpload.ts` — один multer для чата и
  тикетов (типы, лимит 20 МБ, папка тенанта), чтобы правила не разъезжались.
- [x] **Плейсхолдер теперь работает.** Форма показывала плейсхолдеры только у поля
  «Файл» (жёсткий `https://...`); теперь он берётся из поля шаблона для текста,
  многострочного текста и числа — ровно там, где конструктор его и предлагает.
- [x] **Предпросмотр шаблона — настоящая форма.** Вместо списка «[Тип: file]» диалог
  рендерит форму ровно так, как её увидит оператор (неактивную): заголовки,
  разделители, все типы полей и кнопка загрузки файла.
- [x] **Тесты.** `ticketData.test.ts` — валидация файлового поля (объект, строка,
  мусор, обязательность); `attachments.test.ts` — `safeDownloadName`. Бэкенд:
