# План переработки UI под LiveChat + полный список функций

## Часть 1. Переработка UI

### 1.1 Виджет клиента (widget.html/js)

**Проблемы текущего UI:**
- Плоский, без брендинга — выглядит как прототип, не как LiveChat
- Нет прехет-экрана (приветственное сообщение до начала чата)
- Нет аватара оператора
- Нет информации «кто отвечает» (имя оператора в хедере)
- Кнопка «Завершить» слишком заметна — клиент не должен думать о закрытии
- Нет оффлайн-сообщения когда операторов нет

**Изменения:**

1. **Прехет-экран** — при открытии виджета без активного чата показывается:
   - Аватар/иконка поддержки
   - Заголовок «Чем можем помочь?»
   - Подзаголовок «Оператор ответит в течение минуты»
   - Поле ввода (вместо немедленного `init_chat` — чат создаётся при первой отправке)
   - Опционально: поле «Ваше имя» (пока не сохраняем, только отображение)

2. **Хедер чата** — при активном чате:
   - Аватар оператора (дефолтная иконка) + имя «Оператор»
   - Статус «онлайн» (зелёная точка)
   - Кнопка свернуть (×) — текущий close-ui
   - Кнопка «Завершить» спрятана в меню (⋮) — не на виду

3. **Сообщения:**
   - Аватар оператора рядом с его сообщениями (маленький круг слева)
   - Время под каждым сообщением (как в мессенджерах)
   - «Двойная галочка» для прочитанных сообщений оператора

4. **Оффлайн-режим:**
   - Если нет операторов онлайн — показывать «Все операторы заняты, ожидайте»
   - Поле ввода всё равно доступно — чат попадёт в очередь

5. **Стилизация:**
   - Закруглённые пузыри как в iMessage/Telegram (не прямоугольные)
   - Плавные переходы между экранами (прехет → чат → рейтинг)
   - Цвет акцента — настраиваемый через CSS-переменную `--accent` (по умолчанию #007bff)

### 1.2 Панель оператора (operator.html/js)

**Проблемы текущего UI:**
- Сайдбар с чатами выглядит как список задач, не как LiveChat
- Нет профиля оператора (статус, аватар)
- Нет табов чатов сверху — переключение только через сайдбар
- Статистика запихнута в сайдбар — должна быть отдельной страницей

**Изменения:**

1. **Верхняя панель (topbar):**
   - Слева: логотип/название «Support Chat»
   - Центр: табы открытых чатов (как вкладки браузера — по одному на активный чат)
   - Справа: статус оператора (🟢 Онлайн / 🟡 Занят / ⚪ Оффлайн) + аватар + выход

2. **Левая панель (сайдбар):**
   - Секция «Ожидающие» — чаты без ответа оператора (подсветка жёлтым)
   - Секция «Активные» — чаты, где оператор уже ответил
   - Каждая карточка чата: «Клиент #N», превью последнего сообщения, время, бейдж непрочитанных
   - Поиск по чатам

3. **Центральная область (чат):**
   - Хедер: «Клиент #N», таймер ожидания, кнопки (закрыть, передать)
   - Зона сообщений (текущая, с улучшенной стилизацией)
   - Внутренние заметки оператора (`message_type: 'note'`, жёлтый фон, не видны клиенту)

4. **Правая панель (опционально):**
   - Информация о чате: рейтинг, время создания, кол-во сообщений
   - Инлайн-список шаблонов (без модалки)

5. **Статистика — отдельная страница stats.html:**
   - Графики (Chart.js или SVG-бары): чаты за неделю, время ответа, рейтинг
   - Таблица операторов: кол-во чатов, ср. время ответа

### 1.3 Страница входа (login.html)

- Лого/брендинг
- Ссылка «Забыли пароль?» (заглушка)
- Анимация загрузки при входе

## Часть 2. Функции по приоритету

### P0 — Критичные (базовые для LiveChat)

#### 2.1 Статусы оператора (онлайн / занят / оффлайн)
**Зачем:** Оператор может быть занят — влияет на маршрутизацию.
**БД:** `ALTER TABLE operators ADD COLUMN status VARCHAR(20) DEFAULT 'online';`
**Backend:**
- Новое WS-событие `operator_status` — оператор меняет статус
- `handler.ts`: хранить статус в `ClientWs.operatorStatus`
- При `init_chat`: если нет онлайн-операторов — отправлять клиенту оффлайн-сообщение
- `services/chat.ts`: `getOnlineOperators()`
**Frontend оператор:** выпадающее меню в topbar
**Frontend виджет:** «Все операторы заняты» если нет online операторов

#### 2.2 Очередь ожидания
**Зачем:** Если все операторы заняты — клиент видит позицию в очереди.
**БД:** `ALTER TABLE chats ADD COLUMN queue_position INTEGER;`
**Backend:**
- `init_chat` проверяет наличие свободных операторов
- Если заняты — чат получает статус `queued`, клиенту отправляется `queue_position`
- Периодическая проверка: когда оператор свободен, первый чат из очереди → `open`
- WS-события: `queue_update`, `chat_accepted`
**Frontend виджет:** экран «Вы в очереди, позиция: N»
**Frontend оператор:** секция «Очередь» в сайдбаре

#### 2.3 Передача чата другому оператору
**Зачем:** Оператор может не знать ответ, либо клиент запросил другого специалиста.
**БД:** `ALTER TABLE chats ADD COLUMN assigned_operator_id INTEGER REFERENCES operators(id);`
**Backend:**
- WS-событие `transfer_chat` — оператор передаёт чат другому
- Целевой оператор получает `new_chat`, исходный удаляется из комнаты
- Системное сообщение: «Оператор Иван передал чат оператору Пётр»
**Frontend оператор:** кнопка «Передать» + выбор оператора из списка

#### 2.4 Внутренние заметки оператора
**Зачем:** Заметка для себя или коллеги, не видна клиенту.
**БД:** уже есть `message_type` — использовать `'note'`
**Backend:** при `message_type = 'note'` — broadcastToRoom фильтрует по role (не отправлять клиенту)
**Frontend оператор:** переключатель «Заметка» рядом с полем ввода, жёлтый фон

### P1 — Высокие (качественный UX)

#### 2.5 Proactive chat (авто-приглашение)
**Зачем:** Оператор видит посетителей сайта и может сам начать диалог.
**Реализация:**
- WS-событие `visitor_page` — клиент отправляет URL текущей страницы
- Оператор видит «Посетители на сайте» (URL + время)
- Кнопка «Пригласить» → клиенту `proactive_invite`
**БД:** таблица `visitors` (session_id, page_url, first_seen, last_seen)

#### 2.6 Предпросмотр ввода клиента
**Зачем:** Оператор видит, что именно клиент печатает — для подготовки ответа.
**Backend:** расширить `typingStart` — добавить `preview` (первые 30 символов)
**Frontend виджет:** отправлять preview при typingStart
**Frontend оператор:** показывать preview под именем клиента

#### 2.7 Информация о клиенте в чате
**Зачем:** Оператор видит контекст — откуда клиент, страница, браузер.
**Реализация:**
- При `init_chat`: URL страницы, User-Agent, язык
- `ALTER TABLE chats ADD COLUMN client_info JSONB;`
- Оператор видит в правой панели

#### 2.8 Browser-уведомления для оператора
**Зачем:** Оператор может не смотреть на панель.
**Реализация:**
- Browser Notification API — запросить разрешение при входе
- При `new_chat` и новом сообщении в неактивном чате — системное уведомление + звук

### P2 — Средние (профессиональный уровень)

#### 2.9 Департаменты/навыки
**Зачем:** Маршрутизация по отделам (продажи, техподдержка, биллинг).
**БД:** таблица `departments`, `chats.department_id`, `operators.departments`
**Frontend виджет:** выбор отдела перед началом чата
**Frontend оператор:** фильтр по отделам

#### 2.10 Лимит одновременных чатов для оператора
**Зачем:** Не перегружать оператора.
**Реализация:** max 3 чата одновременно, авто-распределение учитывает загруженность

#### 2.11 История чатов клиента
**Зачем:** Оператор видит предыдущие обращения.
**Реализация:** `client_id` связывает чаты одного клиента, API `GET /client-history/:clientId`

#### 2.12 Поиск по сообщениям
**Зачем:** Найти конкретное обращение.
**API:** `GET /search?q=...&limit=20`
**Frontend оператор:** поле поиска в хедере

### P3 — Низкие (nice-to-have)

#### 2.13 Чат-бот для маршрутизации
Автоматический сбор информации до оператора через дерево вопросов в JSON.

#### 2.14 Cobrowsing
Оператор видит страницу клиента. Упрощённая версия: скриншот по кнопке (html2canvas).

#### 2.15 Email-уведомления оператору
nodemailer — при новом чате если нет онлайн-операторов.

#### 2.16 Экспорт статистики
`GET /stats/export?format=csv&from=...&to=...`, кнопка «Скачать CSV».
