# План реализации функционала тегов и информации о клиенте

## Цель
Добавить в систему функционал работы с тегами для чатов и отображение информации о клиенте в панели оператора.

## Бэкенд

### Изменения в базе данных
1. Добавить таблицу `tags`:
   - id (INT, PK, AI)
   - name (VARCHAR)
   - color (VARCHAR, optional) - для визуального wyróżнения
   - created_at (TIMESTAMP)

2. Добавить таблицу `chat_tags` (many-to-many):
   - chat_id (INT, FK -> chats.id)
   - tag_id (INT, FK -> tags.id)
   - created_at (TIMESTAMP)

### Изменения в маршрутах
#### admin.ts
- GET /admin/tags - получить список всех тегов
- POST /admin/tags - создать новый тег
- DELETE /admin/tags/:id - удалить тег

#### chat.ts
- GET /chats?tagId=:tagId&status=:status&from=:from&to=:to - получить чаты с фильтрацией (для архива)
- PUT /chats/:chatId/tag - назначить тег чату (тело: { tagId: number })
- DELETE /chats/:chatId/tag/:tagId - удалить тег с чата

### Сервисы
- Обновить сервис чатов для работы с тегами (назначение, получение, фильтрация)

## Фронтенд

### Админ-панель (admin.html/admin.js)
1. Добавить новую кнопку в боковое меню:
   ```html
   <button class="nav-btn" data-page="tags" onclick="switchPage('tags')">
       <span class="nav-icon">🏷️</span><span class="nav-text">Теги</span>
   </button>
   ```
2. Добавить новую страницу `page-tags`:
   - Карточка с заголовком "Теги"
   - Кнопка "Создать тег" (открывает модальное окно)
   - Таблица существующих тегов (ID, Название, Цвет, Действия)
   - Модальное окно создания/редактирования тега:
     * Поле ввода названия
     * Поле выбора цвета (color picker)
     * Кнопки Сохранить и Отмена

### Панель оператора (operator.html/operator.js)
1. Добавить информацию о клиенте в правую панель:
   - Заменить содержимое div#rp-info на:
     ```html
     <div class="rp-row"><span class="label">Клиент:</span><span class="value" id="client-name">—</span></div>
     <div class="rp-row"><span class="label">Устройство:</span><span class="value" id="client-device">—</span></div>
     <div class="rp-row"><span class="label">Регион:</span><span class="value" id="client-region">—</span></div>
     ```
   - При выборе чата заполнять эти поля данными из объекта чата (clientName, device, region)

2. Добавить функцию назначения тега чату:
   - В чат-хедере (рядом с кнопками Шаблоны, Файл, Заметка) добавить кнопку:
     ```html
     <button class="input-btn" title="Тег" onclick="openTagSelector()">Тег</button>
     ```
   - Модальное окно выбора тега:
     * Список всех тегов (поле поиска по названию)
     * При выборе тега - назначить его текущему чату через PUT /chats/:chatId/tag
     * После успешного назначения обновить отображение тега в чат-хедере (например, бейдж рядом с названием чата)

3. Архив:
   - Добавить панель фильтров над списком архива:
     * Выбор статуса (открытый/закрытый)
     * Ввод диапазона дат
     * Множественный выбор тегов (чекбоксы или мультиселект)
     * Кнопка "Применить"
   - Изменить загрузку спи архива на использование фильтров:
     * GET /chats?tagId[]=:tagIds&status=:status&from=:from&to=:to
   - Отображать теги у каждого элемента архива (в архив-итем)

### Общие изменения
- Обновить стили для бейджей тегов (используя цвет из тега)
- Добавить обработку ошибок и состояния загрузки
- Обеспечить доступность (aria-атрибуты, фокус)

## Варианты реализации

### Вариант 1: Теги только в архиве
- Админ панель: полное управление тегами
- Оператор панель: только вид тегов в архиве и чатах, без возможности назначения
- Плюсы: проще реализовать, меньше прав в операторке
- Минусы: оператор не может помечать чаты

### Вариант 2: Теги с цветовой кодировкой
- Добавить поле color в сущность тега
- Отображать теги как цветные бейджи
- Плюсы: лучше визуальное восприятие
- Минусы: сложнее выбор цвета, нужно хранить цвет

### Вариант 3: Группировка тегов
- Добавить категории тегов (например, по типу проблемы)
- Плюсы: лучше организация большого числа тегов
- Минусы: сложнее структура, может быть избыточно для MVP

Выбранный вариант: Вариант 5 (множественные теги на чат) с цветовой кодировкой для лучшей визуализации. Это позволит гибкую классификацию чатов, улучшенную фильтрацию в архиве и визуальное отличие тегов.

## Критерии готовности
- [ ] Администратор может создавать, редактировать и удалять теги
- [ ] Оператор видит информацию о клиенте (имя, устройство, регион) в правой панели
- [ ] Оператор может назначать тег текущему чату и видеть его в интерфейсе
- [ ] В архиве оператор может фильтровать чаты по тегам, статусу и датам
- [ ] Теги отображаются с их цветами в интерфейсе
- [ ] Все изменения сохраняются и синхронизируются через API
