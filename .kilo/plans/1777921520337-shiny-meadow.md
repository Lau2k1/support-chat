# План исправления багов в админ-панели и аутентификации

## Цель
Исправить следующие проблемы:
1. Кнопка "Создать тег" в админ-панели не работает.
2. В админ-панели появились две вкладки "Настройки".
3. После перезапуска сервера не требуется повторная авторизация в логин-панели.

## Анализ проблем

### Проблема 1: Кнопка "Создать тег" не работает
- Функция `saveTag()` в `admin.js` выглядит корректно.
- Возможные причины: ошибка в HTML (отсутствие onclick, неправильный ID модала), проблема с API (маршрут `/admin/tags` не работает), или JavaScript ошибка.
- Нужно проверить: модал `tagModal`, кнопку `saveTag()`, и обработку ответа от сервера.

### Проблема 2: Две вкладки "Настройки"
- В `admin.html` есть два `<button class="nav-btn" data-page="settings">` (строки 156 и 163).
- Это дубликат, второй нужно удалить.

### Проблема 3: Нет повторной авторизации после перезапуска
- JWT токен хранится в localStorage и не проверяется на истечение при загрузке страницы.
- В `checkAdmin()` проверяется наличие токена, но не его валидность/истечение.
- Нужно добавить проверку на истечение токена в `checkAdmin()` или при загрузке.

## План исправления

### Шаг 1: Исправить дубликат вкладки "Настройки"
- Удалить второй `<button class="nav-btn" data-page="settings">` в `admin.html` (строка 163).

### Шаг 2: Запустить миграцию базы данных
- Проблема: столбцы `client_name`, `client_device`, `client_region` не существуют в таблице `chats`.
- Решение: добавить ALTER TABLE в `init.sql` для добавления этих столбцов к существующей таблице.
- Запустить `npm run migrate` в директории `backend`.

### Шаг 3: Диагностировать кнопку "Создать тег"
- Проверить HTML: убедиться, что кнопка имеет `onclick="saveTag()"`.
- Проверить JavaScript: добавить console.log в `saveTag()` для отладки.
- Проверить API: убедиться, что маршрут `/admin/tags` работает (запустить сервер и протестировать POST запрос).
- Если API не работает, проверить backend роуты в `admin.ts`.
- Анализировать конкретную ошибку, показанную пользователем (нужна детализация ошибки).

### Шаг 4: Исправить аутентификацию после перезапуска
- В `checkAdmin()` добавить проверку на истечение токена:
  - Распарсить JWT и проверить поле `exp`.
  - Если токен истёк, очистить localStorage и перенаправить на login.html.
- Обновить `parseJwt()` если нужно для обработки ошибок.

## Критерии готовности
- [ ] Миграция базы данных выполнена успешно, столбцы добавлены.
- [ ] Кнопка "Создать тег" успешно создаёт тег и обновляет список.
- [ ] В админ-панели только одна вкладка "Настройки".
- [ ] После перезапуска сервера с истёкшим токеном требуется повторная авторизация.

## Риски
- Изменения в аутентификации могут повлиять на пользовательский опыт (автоматический логаут).
- Нужно протестировать на реальном сервере с базой данных.
