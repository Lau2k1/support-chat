# План: Регистрация операторов + Админ-панель

## Обзор

Реализовать:
1. **Регистрацию операторов по инвайт-коду** — админ генерирует одноразовые коды, оператор регистрируется через форму
2. **Админ-панель** (отдельная страница `admin.html`) — управление операторами, статистика по операторам, аудит чатов, настройки системы

## 1. Изменения в БД (`backend/src/db/schema/init.sql`)

### 1.1. Добавить колонку `role` и `is_enabled` в таблицу `operators`

```sql
ALTER TABLE operators ADD COLUMN IF NOT EXISTS role VARCHAR(20) DEFAULT 'operator';
ALTER TABLE operators ADD COLUMN IF NOT EXISTS is_enabled BOOLEAN DEFAULT true;
```

- `role`: `'admin'` | `'operator'` — по умолчанию `'operator'`
- `is_enabled`: если `false`, оператор не может войти (аккаунт отключён админом)

### 1.2. Новая таблица `invite_codes`

```sql
CREATE TABLE IF NOT EXISTS invite_codes (
    id SERIAL PRIMARY KEY,
    code VARCHAR(32) UNIQUE NOT NULL,
    created_by INTEGER REFERENCES operators(id),
    used_by INTEGER REFERENCES operators(id),
    used_at TIMESTAMP,
    expires_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 2. Изменения в middleware (`backend/src/middleware/auth.ts`)

### 2.1. Расширить `AuthenticatedRequest`

Добавить `role` в тип `user`:
```ts
user?: { id: number; name: string; role: string };
```

### 2.2. Добавить `adminMiddleware`

```ts
export function adminMiddleware(req, res, next) {
  if ((req as AuthenticatedRequest).user?.role !== 'admin') {
    return res.status(403).json({ error: 'Admin access required' });
  }
  next();
}
```

## Баг: логин не перекидывает на operator.html

### Корневая причина

Race condition между WS-сообщениями `auth` и `operator_join` в `operator.js:101-109`.

После добавления проверки `is_enabled` в WS handler (`handler.ts:34`), `auth` case стал **асинхронным** (делает `pool.query`). Но `operator.js` отправляет `operator_join` **сразу** после `auth`, не дожидаясь подтверждения:

```js
ws.onopen = () => {
    ws.send(JSON.stringify({ type: "auth", token }));      // async — делает DB query
    ws.send(JSON.stringify({ type: "operator_join" }));     // приходит до завершения auth
    ws.send(JSON.stringify({ type: "operator_status", ... }));
};
```

Порядок обработки:
1. `auth` приходит → начинает `pool.query` (асинхронно)
2. `operator_join` приходит → `ws.role` ещё `undefined` → `handler.ts:48` отправляет `auth_error`
3. `operator.js:166` получает `auth_error` → `location.href = "login.html"` — редирект обратно

### Исправление

В `frontend/operator.js`: отправлять `operator_join` и `operator_status` только **после получения подтверждения** от сервера об успешной авторизации.

**Вариант**: добавить новый тип WS-ответа `auth_ok` или использовать существующую логику — отправлять `operator_join` только после получения `init_operator` или другого подтверждения.

Проще всего: отправлять `operator_join` после задержки или по событию. Лучший вариант — сервер отправляет `auth_ok` после успешного auth, а клиент ждёт его.

### Файлы для изменения

1. **`backend/src/ws/handler.ts`** — после успешного `auth` отправлять `safeSend(ws, { type: 'auth_ok' })`
2. **`backend/src/ws/types.ts`** — добавить `{ type: 'auth_ok' }` в `OutgoingMessage`
3. **`frontend/operator.js`** — в `ws.onopen` отправлять только `auth`; при получении `auth_ok` отправлять `operator_join` и `operator_status`

`npm run seed` падает с ошибкой `column "role" of relation "operators" does not exist`. Причина: в `init.sql` таблица `operators` создаётся через `CREATE TABLE IF NOT EXISTS`, но если таблица уже существует в БД, новые колонки (`role`, `is_enabled`, `created_at`) не добавляются. `CREATE TABLE IF NOT EXISTS` пропускает таблицу целиком.

## Исправление

Добавить в `init.sql` после `CREATE TABLE operators` три `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`:

```sql
ALTER TABLE operators ADD COLUMN IF NOT EXISTS role VARCHAR(20) DEFAULT 'operator';
ALTER TABLE operators ADD COLUMN IF NOT EXISTS is_enabled BOOLEAN DEFAULT true;
ALTER TABLE operators ADD COLUMN IF NOT EXISTS created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP;
```

Это гарантирует, что новые колонки появятся и при чистой установке, и при миграции существующей БД.

Файл: `backend/src/db/schema/init.sql`
